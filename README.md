你好！作为运维工程师，Python 实战的核心不在于算法复杂度，而在于**系统交互、自动化流程、文本处理和异常健壮性**。

下面为你设计了一套循序渐进的实战练习路线，共分为 5 个阶段。每个阶段包含一个贴近真实生产环境的题目，建议按顺序完成。

---

### 🟢 阶段一：系统信息探测与文件处理
> **目标**：掌握 `os`/`pathlib`、文件读写、字符串解析，建立"脚本即工具"的思维。

#### 题目：磁盘空间巡检器
编写一个脚本，扫描指定目录（默认 `/var/log`）下所有超过 **100MB** 的文件，输出表格化报告（路径、大小、最后修改时间），并按大小降序排列。若目录不存在或无权限，需优雅提示而非崩溃。

**核心考点**：
-   `pathlib.Path.rglob()` 递归遍历
-   文件大小的人类可读格式化（B/KB/MB/GB）
-   异常捕获（`PermissionError`, `FileNotFoundError`）
-   命令行参数解析（`argparse` 支持自定义目录和阈值）

**进阶挑战**：增加 `--delete` 参数，交互式确认后删除匹配文件；增加 `--output report.csv` 导出功能。

---

### 🔵 阶段二：日志分析与正则提取
> **目标**：熟练使用 `re`、生成器处理大文件、数据结构统计。

#### 题目：Nginx 访问日志分析器
解析标准 Nginx combined 格式日志，统计以下指标并输出 JSON：
1.  Top 10 访问量最高的 IP
2.  HTTP 状态码分布（如 `{200: 8500, 404: 320, 500: 15}`）
3.  每分钟的请求数趋势（用于发现流量尖峰）
4.  响应时间 > 1s 的请求列表

**核心考点**：
-   正则表达式命名分组提取字段
-   生成器逐行读取（避免 GB 级日志撑爆内存）
-   `collections.Counter` / `defaultdict` 高效统计
-   `datetime` 解析与时间桶聚合

**进阶挑战**：支持 gzip 压缩日志（`gzip.open`）；增加 `--since "2026-10-13 10:00"` 时间过滤；用 `rich` 库美化终端输出。

---

### 🟡 阶段三：进程管理与服务编排
> **目标**：掌握 `subprocess`、信号处理、并发执行。

#### 题目：批量服务健康检查与自愈守护
编写一个守护脚本，从配置文件（YAML/TOML）读取服务列表（含检查命令、重启命令、最大重试次数）。每隔 N 秒执行健康检查，失败时自动重启并记录日志，连续失败超阈值则发送告警（模拟即可）。

**核心考点**：
-   `subprocess.run()` 超时控制与返回值判断
-   YAML/TOML 配置加载与校验
-   日志模块 `logging` 规范输出（含轮转）
-   信号处理（`SIGTERM` 优雅退出，避免僵尸进程）
-   状态持久化（记录上次检查结果，避免重复告警）

**进阶挑战**：使用 `concurrent.futures.ThreadPoolExecutor` 并行检查多个服务；增加指数退避重试策略；支持 dry-run 模式。

---

### 🟠 阶段四：网络自动化与 API 交互
> **目标**：掌握 `requests`/`httpx`、JSON 处理、认证与安全。

#### 题目：多云资源巡检仪表盘后端
对接至少两个云平台 API（如阿里云 + AWS，或 Prometheus + Grafana），拉取实例列表、CPU/内存使用率、安全组规则，合并为统一数据模型，暴露为 REST API 供前端展示。

**核心考点**：
-   HTTP 会话复用、分页处理、速率限制应对
-   API 密钥安全管理（环境变量 / Vault，绝不硬编码）
-   数据标准化与异常响应处理
-   Flask/FastAPI 基础路由与中间件
-   单元测试 Mock 外部 API

**进阶挑战**：增加缓存层（Redis/SQLite）减少 API 调用；实现增量同步；添加 OpenAPI 文档自动生成。

---

### 🔴 阶段五：综合工程化实战
> **目标**：将前四阶段能力整合，产出可交付、可维护的生产级工具。

#### 题目：自动化发布验证流水线
构建一个 CLI 工具，串联以下流程：
1.  从 GitLab/GitHub Webhook 接收部署事件
2.  SSH 到目标机器执行冒烟测试脚本
3.  收集测试结果 + 系统指标 + 应用日志片段
4.  生成 HTML 报告并上传至对象存储
5.  通过钉钉/飞书/Slack 推送摘要通知

**核心考点**：
-   全流程异常处理与回滚机制
-   SSH 自动化（`paramiko` / `asyncssh`）
-   模板引擎（Jinja2）生成报告
-   异步 I/O（`asyncio`）提升多节点效率
-   项目结构规范（`pyproject.toml`、类型注解、CI 集成）
-   完善的 README + CHANGELOG + 使用示例

**进阶挑战**：支持插件化扩展测试项；增加审批门禁；对接 CMDB 获取机器清单；编写完整的测试套件。

### 💡 练习建议

| 原则 | 说明 |
| :--- | :--- |
| **先跑通再优化** | 每个阶段先写出能用的版本，再迭代重构 |
| **模拟真实环境** | 用 Docker/Vagrant 搭建测试环境，别在真机上练手 |
| **写文档和注释** | 运维脚本的生命周期往往比作者在职时间长 |
| **版本控制** | 每个练习都用 Git 管理，养成 commit message 规范 |
| **安全第一** | 永远假设输入不可信，永远不硬编码密码 |

你可以从**阶段一**开始动手，完成后把代码或遇到的问题发给我，我会给出针对性反馈和下一阶段的具体指导。准备好就开始吧！
